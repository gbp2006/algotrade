# AGENTS.md — песочница алготрейдинга

Правила для агентов. Цель: минимум токенов, максимум повторяемости.

## Что читать в первую очередь

1. `PROGRESS.md` — состояние проекта, последние результаты, открытые вопросы (~2 КБ).
2. `docs/decisions.md` — принятые решения и почему (одна строка на решение).
3. `docs/strategies/*.md` — канонические описания систем.
4. Код — только тот файл, который правишь.

**Никогда** не читать файлы из `data/` (гигабайты) и не выводить в чат длинные таблицы.
Скрипты обязаны печатать не больше 6 строк сводки; подробности — в `reports/`.

## Структура

```
algo/            движок и стратегии (data.py, engine.py, iss.py, strategies/)
scripts/         запускаемые скрипты: 01_… 02_… по порядку
tests/           юнит-тесты движка
web/             локальная панель (FastAPI + Jinja)
data/            симлинк на /mnt/DiskD/MOEX/Исторические данные (не коммитить)
materials/       материалы автора: записи счёта, TG-дампы, лекции
cache/iss/       сырые выгрузки MOEX ISS
docs/            решения, how-to, спецификации систем, источники
reports/         отчёты для человека (*.md, эквити *.csv)
results/         runs.csv — журнал прогонов (машиночитаемый)
sessions/        журнал работы: <YYYY-MM-DD_HH-MM_slug>/notes.md
infra/db/        индекс истории (memory.py, memory.db) — производный
infra/exports/   JSON-бэкапы перенесённых чатов
assets/          исходники картинок
.venv/           python песочницы (requirements.txt)
```

## Сессии и память

- Запуск: алиас `algo` — изолированный профиль OpenCode (свои конфиг, БД
  сессий и фоновый сервис).
- Папка сессии: `sessions/YYYY-MM-DD_HH-MM_slug/notes.md`; подробности —
  skill `session-workflow`.
- `INDEX.md` — производный от `sessions/`; статусы тянет
  `./infra/db/memory.py index-sync` из записей «Конец:».
- История: `./infra/db/memory.py brief|lookup|search|outline` или MCP `memory`.
- В индекс входят `sessions/`, `PROGRESS.md`, `docs/`, `reports/`; данные,
  материалы, кэш и код — нет.

## Обязательные правила

- Новый прогон → строка в `results/runs.csv` через `algo.results.record()`.
- Вывод в консоль: `name, сделок, net, PF, DD` — одна строка на вариант.
- Большие выгрузки — в `reports/`, а в чат только путь.
- Данные не копировать: `data/` — симлинк, чтение через `algo.data.load_txt`.
- Тяжёлые данные кэшировать: `algo.data.load_cached()` (pickle в `.cache/`).
- Меняешь модель исполнения или издержек — сначала обнови `docs/decisions.md`.

## Модель исполнения (не менять молча)

- сигнал по `close` бара → сделка по `open` следующего бара;
- комиссия 0.01% за сторону, проскальзывание 1 тик;
- CNY: шаг 0.001, множитель 1000 ₽; Si: шаг 1.0, множитель 1 ₽;
- решения по субботам/воскресеньям отключаются (`skip_weekend=True`).

## Две среды: десктоп-песочница и тестовый сервер (WSL)

- **Песочница — этот ПК** (`zt-desktop`, проект в `/mnt/DiskD/opencode-algo`,
  OpenCode-профиль `algo`): единственное место, где работает агент — проверка
  гипотез, код, выкачивание данных, юнит-тесты, бэктесты, локальная панель
  (`./run.sh dash`), ручные прогоны, правки движка/стратегий.
- **WSL** (`zt@SERVER`, SSH `wsl-algo` → `192.168.0.230`, проект в `/home/zt/algotrading`)
  — **тестовый сервер, где работают торговые роботы**, а не песочница: там
  живёт веб-панель (`algotrading-web.service`, :8080), сервисы таймеров
  (`algotrading-daily/morning/friday`) и бумажный контур по живым котировкам
  (`paper-live`). OpenCode и агентских сессий там нет.
- **На этом ПК (десктопе) никаких панелей и сервисов роботов не запускать** —
  только код, тесты, бэктесты, выкачивание данных, локальная проверка.
- Песочница (`algo`) есть **только на ПК и не дублируется** на WSL: правки в
  код/скрипты/исправления сначала **коммитятся в git-репозиторий** на ПК
  (локально + `git push` на https://github.com/gbp2006/algotrade), и только
  после этого копируются на WSL (минимальный набор файлов + скрипт исправления)
  при необходимости, затем перезапускается сервис на WSL через sudo.
- Если правка относится к торговым роботам (панель, таймеры, watchdog, конфиги
  сервисов) — она пишется и проверяется на WSL, а не на десктопе.
