# AGENTS.md — песочница алготрейдинга

Только торговля, роботы, алгоритмы. Общие и бытовые темы — в песочнице `oc`
(`/mnt/DiskD/opencode-hub`, профиль `opencode`); истории и индексы не смешивать.
Цель: минимум токенов, максимум повторяемости.

## Читать в первую очередь

1. `docs/ONBOARDING.md` — обязательная точка входа для любого ИИ/разработчика:
   стек, команды, проверки, инварианты, адреса, что нельзя менять без ADR.
2. `PROGRESS.md` — статус, цифры, открытые вопросы (~3 КБ).
3. `docs/MODULES.md` — описание **каждой** части проекта (роль, входы, выходы,
   сайд-эффекты, тесты). Новый модуль/секция/API без записи сюда — не принимается.
4. `docs/decisions.md` — последние ADR; архив `docs/decisions-archive-2026-11-24.md`
   искать grep/memory, не читать целиком.
5. `docs/ARCHITECTURE.md`, `docs/strategies/*.md` — состав систем и канон стратегий.
6. Полные правила среды, структуры и исполнения — `docs/sandbox-rules.md`.
7. Код — только правимый файл; `data/`, `materials/`, `cache/` не читать.

## Бюджет контекста

- История — через `./infra/db/memory.py brief|lookup|search|outline` (MCP `memory`),
  а не чтением длинных `notes.md`. Вывод скриптов ≤6 строк, детали — в `reports/`.
- Одна сессия — одна тема; завершать записью «Конец:» (skill `session-workflow`).
  Длинные сессии резко увеличивают повторное чтение контекста.
- Автоматика раз в 4 ч (`scripts/94_context_cleanup.py`): принудительный `/compact`
  крупным сессиям, сборка и проверка индекса с автоисправлением расхождений и
  защитой от чужих доменов, учёт токенов в `results/token_usage.json`, уборка
  производных. В конфиге компакт — примерно при 65% окна.
- MCP-профили: `python3 scripts/96_mcp_profile.py work|research|broker`; по умолчанию
  только `memory`. Профиль подхватывается новой сессией после перезапуска сервиса.

## Обязательное

- Любая новая часть проекта (модуль, класс, endpoint, секция UI, скрипт, схема
  БД, systemd-юнит) обязана получить строку в `docs/MODULES.md`: **роль / входы /
  выходы и сайд-эффекты / зависимости / тесты**. Изменение команд или адресов —
  одновременно править `docs/ONBOARDING.md`.
- Новый прогон → строка в `results/runs.csv` через `algo.results.record()`;
  в консоль — `name, сделок, net, PF, DD` одной строкой на вариант.
- Данные не копировать: `data/` — симлинк, чтение через `algo.data.load_txt`;
  тяжёлые данные — `algo.data.load_cached()`.
- Меняешь модель исполнения или издержки — сначала ADR в `docs/decisions.md`.
- Модель исполнения: сигнал по `close` → сделка по `open` следующего бара;
  0.01% за сторону + 1 тик; CNY шаг 0.001 × 1000 ₽, Si шаг 1.0 × 1 ₽;
  `skip_weekend=True`.
- На десктопе не запускать панели и сервисы роботов — только код, тесты,
  бэктесты, локальная проверка. Правки для WSL — на WSL, после commit + push;
  правки по роботам (панель, таймеры, watchdog) — писать и проверять на WSL.
- Секреты — в `auth.json` или `{env:...}`, не в конфигах и чате.
