# Сессия — G3: безопасное исполнение заявок

## 2026-11-20 17:35 — Запрос и границы
Пользователь выбрал G3 как следующий шаг после аудита цикла. Правило:
реальные заявки не включать (`FINAM_ALLOW_TRADING=0` на WSL), код не подключать
к `paper-live`, пока не проверена схема Finam и не пройдена репетиция.

## 2026-11-20 17:36 — Реализация каркаса
- `algo/broker/execution.py`: `Order`, `Limits`, `Result`, `OrderGateway`.
  Перед отправкой: флаг торговли → lock `results/live.lock` → дубль `client_id`
  → лимиты (qty, номинал, дневной убыток, список символов) → транспорт.
  Любая попытка пишется в `results/live.csv` (`blocked/rejected/duplicate/
  sent/error`), lock снимается в `finally`, ошибка транспорта не теряется.
- `FinamBroker.place_limit()`: лимитная заявка с price/time_in_force,
  повторная проверка флага. Поле `clientOrderId` **не выдумываем** — сверить
  с документацией перед боевым включением.
- `positions_from_response()` / `reconcile()`: нормализация ответа брокера и
  список расхождений; неизвестный формат — явная ошибка.
- Тесты: `tests/test_execution.py` (9) + payload-тест в `test_broker.py`.
  **44 теста OK**, настоящий API не вызывается.
- Документы: `docs/live-execution.md`, обновлены `docs/live-gates.md` и ADR.
