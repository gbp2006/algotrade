# Сессия — позиция живого робота в панели

## 00:04 — старт: убрать расхождение UI и факта счёта

После прошлых правок (лимит по итоговой позиции, зелёный WSL-прогон) оставался
пункт: у `prostushka-test-1` нет записи в `runtime_state`, поэтому таблица
«Роботы» показывает позицию 0, хотя брокер держит −2 CNY. Задача — сделать
позицию видимой, не менять модель исполнения.

Разобрал контур: `webui/src/sections/Robots.tsx:165` берёт позицию из

Запись рантайма из бумажного контура делает `instance_configs.migrate_runtime_from_paper`,
но на живые инстансы она не распространяется.

## 00:08 — реализация

В `scripts/34_live_execute.py`:

- новая функция `sync_live_runtime(store, updates)` — только запись факта,
  заявки/STOP/настройки не трогаются; `set_runtime` перезаписывает всю строку,
  поэтому недостающие поля (equity, last_price, note) берутся из прежнего
  состояния; ошибки одного инстанса или БД не роняют прогон;
- после прогона по каждому счёту повторно читаются позиции брокера; при
  недоступности API используется позиция до отправки (dry-run её не меняет);
- для каждого робота плана (`plan["robots"]`) пишутся symbol, позиция счёта,
  equity счёта, цена сигнала, решение вида `2026-11-26 13:57 planned` и пометка
  «общая для роботов счёта»;
- решение по символу сохраняется в `decisions[(account, symbol)]`, чтобы в UI
  был виден статус последнего прогона.

В `tests/test_live_execution.py` — класс `TestLiveRuntime` (3 теста): слияние с
прежним рантаймом, устойчивость к недоступной БД, запись нового инстанса.
`docs/MODULES.md` и `PROGRESS.md` обновлены. ADR не потребовался: модель
исполнения, издержки, экспозиции и стоп-флаги не меняются.
