## 23.11, 23:00–00:30 — код и выкладка

- Журнал сделок: SQLite `infra/db/trades.db` как источник правды (уникальный
  `client_order_id`, `order_events`, `trades`, WAL, `backup()`), `live.csv` —
  зеркало; миграция старых строк. `docs/trade-journal.md`.
- Справочник инструментов: `infra/db/instruments.db`, полный каталог Финама
  (~127 тыс. уникальных символов) для поиска + топ ликвидных с MOEX ISS
  (30 фьючерсов по ОИ, 30 акций по обороту) + избранное. В форму робота по
  умолчанию подаются избранное и ликвидные.
- Ошибка, исправлена: собственная формула сайзинга «18 000 ₽ на лот из DD»
  была не авторской. В TG Силаева (25.04.2025) прямо сказано: управления риском
  через `% на сделку` нет, риск идёт через размер позиции, не более 200% счёта
  на валютных фьючах, на волатильности сайз режется. Формула заменена на
  `лот = floor(equity × экспозиция / (цена × множитель))` через
  `size_contracts()`; ATR-резка на старте боя **не включается** (отдельное
  решение позже). ADR об отклонении собственной формулы есть.
- Поле «капитал счёта» удалено из боевых счетов и роботов полностью: размер
  берётся только из `equity` брокера (`account_equity()`). Колонка
  `instances.capital` сохранена только для виртуальных депозитов бумаги.
- `source_config`: живой робот ссылается на бумажного (`p-base`) — иначе
  сгенерированный панелью id не находил решений в `paper.csv` и заявок не было.
- Ручной запуск: `POST /api/live-run` (dry-run / один `--arm` прогон, флаг
  только в дочернем процессе). Кнопки в карточке «Ручной запуск боя».
- Постоянная торговля: `algo/live_control.py` + `GET/POST /api/live-control`.
  Тумблер создаёт юниты `algotrading-live.service/.timer`, ставит Пн–Пт 14:00,
  `FINAM_ALLOW_TRADING=1` только в юните, `.env` не трогает; проверки: активный
  живой робот, счёт, отсутствие `STOP_REAL`. Пользователь тумблер включил.
- Кнопки: «закрыть позиции» (с подтверждением), rebalance/close фонда; по
  умолчанию `planned`, реальная отправка через `ALGO_CLOSE_ARMED` /
  `ALGO_MM_ARMED`. Спец `money_market` портирован с OsEngine `TmonRebalancer`
  (режимы Off/TwiceADay/OnceADay/OnlyClose, min balance 5000, спред 0.01%).
- Параллельная сессия выложила общий `web/static/app.css`, все шаблоны и
  `web/static/*` в whitelist; её коммиты не смешивались с нашими.
- Сайдбар: `sidebar.js` на `/trade` и `/robots` показывает только
  `/api/instances?mode=live`; на «Тесте» — все стратегии. Ссылки из «Теста»
  ведут на `/robots?mode=paper`, из «Торговли» — на `/robots?mode=live`.
- Стиль `/robots` приведён к общему (сайдбар, navtabs, CSS).

## Ошибки и как обходили

- `test_broker::test_secret_required` падал после появления auth.json — тест
  теперь подменяет `AUTH_PATH` на временный файл.
- `/api/service-key` давал 500 из-за `list(...).keys()` — исправлено.
- При выкладке стилей `app.css` был не в whitelist и отсутствовал на WSL —
  параллельная сессия добавила `web/static/*` и выложила.
- `test_rollover_live.py` на WSL падал по SSL к ISS (`CERTIFICATE_VERIFY_FAILED`)
  после полуночи — сетевая/сертификатная проблема, не код.
