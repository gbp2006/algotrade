# Сессия — общее хранилище баров для песочницы и WSL

## 2026-11-20 16:20 — Требование пользователя
БД нужна **в двух экземплярах**: в песочнице `algo` тестируем стратегии,
на WSL сравниваем с реальной торговлей. Одна схема и один код в обоих местах,
между ними — перенос срезов.

## 2026-11-20 16:22 — Дизайн
Причина двух экземпляров: в песочнице бэктест — контролируемый реплей
(один код, одни данные, без API и systemd), на WSL работает весь боевой стек
(таймеры, Finam API, резолв контрактов, живые котировки, STOP, веб-панель).
Сверка с историей — единственная end-to-end проверка, что боевой стек всё ещё
даёт те же решения, что чистый бэктест.

Схема SQLite `infra/db/market.db`:
- `bars(symbol, tf, dt, source, o,h,l,c,v, updated_at)`,
  PRIMARY KEY `(symbol, tf, dt, source)` WITHOUT ROWID;
- `meta(symbol, tf, source, last_dt, rows, imported_at)`;
- WAL, `synchronous=NORMAL`; таймзона naive MSK — как в `load_txt`/`decision`.

Ключевые решения:
- `source` в PK: `finam_live` (на чём решает робот), `iss` (независимая
  сверка фида), `finam_archive` (длинная история). Один бар из разных
  источников не затирает другой.
- `updated_at` + `ON CONFLICT ... WHERE excluded.updated_at >= bars.updated_at`:
  двусторонний обмен BETWEEN машинами идемпотентен, побеждает свежая версия.
- `ON CONFLICT DO UPDATE` заодно лечит главный дефект append-файла:
  незакрытый бар, записанный в 16:10, больше не остаётся с кривым close —
  следующий опрос его перезаписывает.
- Каноничный M1 + M5 Финама отдельным source: агрегация M1→M5 у Финама
  не совпадает с нашей (4 тика), пересчитывать M5 нельзя.

## 2026-11-20 16:24 — Реализация
- `algo/store.py` — `init_db`, `upsert`, `read`, `raw`, `stats`.
- `scripts/00_store.py` — CLI: `init|import-txt|import-finam|export|import-csv|stats`.
- `run.sh` — команда `store`.
- `scripts/10b_append_finam.py` — после записи CSV делает `upsert` в БД
  (source=`finam_live`, tf=M5), поэтому 10-минутный таймер на WSL наполняет БД сам.
- ADR в `docs/decisions.md`.
