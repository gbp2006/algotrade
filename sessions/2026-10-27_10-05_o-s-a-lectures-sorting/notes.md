### 12:00 — Баг: «сегодняшние даты» у 35 новых файлов (жалоба пользователя)
- Пользователь: у «С# для алготрейдера» и ещё 35 файлов дата 2026-10-27 —
  ложь, лекции выходили раньше.
- Причина: в sort.py `fetch_dates()` передавал URL в yt-dlp **через stdin**,
  а yt-dlp их так не принимает («You must provide at least one URL»,
  RC=2). Даты не получались молча → срабатывал запасной вариант `date_for`:
  mtime файла = день скачивания = 27.10.2026. Первые 390 файлов не пострадали
  — их даты были получены ранее отдельным корректным скриптом (xargs по URL).
- Фикс в sort.py: (1) `fetch_dates` передаёт URL аргументами (пакетами по 20
  после `--`), печатает число полученных дат и stderr при неудаче;
  (2) добавлен режим `renew`: для файлов уже в новом формате (без ID)
  дата в имени сверяется с кэшем по media-index.txt — при расхождении
  префикс перезаписывается.
- Результат: запрошено 38, получено 35 (3 — Private, см. ниже), файлы
  переименованы на реальные даты: С# для алготрейдера → 11–13.11.2024 и т.д.,
  «Введение в алготрейдинг» → 10–14.04.2025, «Тренд через Walk Forwards» →
  17.04–04.05.2025, «Подгрузка данных с Финам» → 24.04.2020.
- Попутно исправлен косяк собственного фикса: двойной прочерк «дата - - Лекция»
  (неправильный срез префикса fname[11:]) → повторным прогоном лечено до
  «дата - Лекция NN».
- Финальная сверка 425 записей индекса: расхождений имени с кэшем дат — 0,
  файлов без даты в имени — 0, файлов с 2026-10-27 — 0, dry-run — 0 действий.
