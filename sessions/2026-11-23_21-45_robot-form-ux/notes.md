# 23.11.2026 — форма «Новый робот»: имя вместо ID и переключатели

### 21:45 — Запрос пользователя
В форме «Новый робот» неудобно: параметры `true/false` показаны текстом, непонятно поле «id инстанса». Пользователь просит: **ID генерировать внутри системы**, а ему оставить поле «Имя», куда он пишет человеческое название.

### 21:50 — Что сделано
- `web/instances_api.py`: генератор `generated_instance_id()` — транслитерация кириллицы, slug, уникальный суффикс `-2/-3`; имя пишется в `note` инстанса (уже отображается в списке под id). Пустое имя → fallback `spec-instrument`.
- `web/templates/robots.html`: поле `id инстанса` заменено на «Имя»; булевы параметры стали чекбоксами-переключателями в create/edit модалках; добавлены русские подписи и подсказки (`short_friday`, `close_friday`, `risk_vol`, `ma_window`, `timeframe`); показаны дефолты spec рядом с описанием (описание «MA40 M5» справочное, реальные дефолты 200/60); режим «бой» блокируется при отсутствии счетов.
- `tests/test_instances_api.py`: 3 теста — генерация id из имени, fallback, разметка формы с чекбоксами. `./run.sh test`: 136 тестов в 20 файлах, зелёные. Документы приведены к 136, добавлены две ADR.

### 22:00 — Конец: форма «Новый робот» переработана — решено
ID теперь внутренний: сервер сам делает slug из имени и добавляет суффикс при коллизии; пользователь видит только «Имя», которое сохраняется как примечание инстанса. Булевы параметры стали переключателями с русскими подписями и подсказками; дефолты spec показаны рядом с описанием, чтобы «MA40 M5» не вводило в заблуждение (фактические дефолты MA200/H1). Бой недоступен без счёта. 136 тестов зелёных, конфигурации и ворота не менялись. Статус: **решено**.
