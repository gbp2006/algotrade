# Восстановление OsEngine MCP и уборка старой копии

## Ход работы

### 14:25 — Диагностика

Пользователь: «почему osengine error». Проверено:

- `http://localhost:6500/api/v2/mcp` → `000`, порт 6500 не слушается,
  процессов `wine`/`OsEngine` нет; панель `:8080` при этом жива.
- В `opencode.jsonc` MCP смотрит на `localhost:6500` с публичным дефолт-ключом
  `osengine-mcp-default-key` (не секрет).
- В `results/health.json` ошибок нет — это локальная проблема OsEngine.

### 14:26 — Первый (ошибочный) запуск

Нашёл `/mnt/DiskD/OsEngine-master/project/OsEngine/bin/Debug/OsEngine.exe`,
запустил его под Wine (`/opt/wine-stable/bin/wine`, WINEPREFIX `~/.wine`) с `-data`.
Порт не поднялся: в `Engine/McpSettings.txt` 3-я строка `IsEnabled=False`.
Включил `True`, перезапустил — MCP поднялся, но отдал версию **2.0.1.9** и 180
инструментов. Это был не тот билд: пользователь заметил несоответствие с
зафиксированным в PROGRESS обновлением до 2.0.2.0.

### 14:30 — Нахождение рабочей копии

Обновлённая копия 23.11 (exe от 18:50, бэкап
`Engine/Updater/Builds/Build_23-11-2026_18-50_github_update`, `IsEnabled=True`)
лежит в `materials/04_Софт_и_инструменты/OsEngine Софт/OsEngine-master`.
Запустил её: `initialize` → `notifications/initialized` → `tools/list` →
`serverInfo.version = 2.0.2.0`, **181 инструмент**, `terminal_get_status` →
`IsOsData`. Артефакты HTTP-проверки — `/tmp/opencode/init.json`, `call.json`
(в контур не входят).

Вывод: причина исходного сбоя — терминал OsEngine вообще не был запущен.
Моя гипотеза про «сброс IsEnabled при обновлении» была неверной: в рабочей
копии настройка включена; `False` был только в старой копии.

### 14:36 — Уборка старой копии

По просьбе пользователя удалил `/mnt/DiskD/OsEngine-master` (804 МБ). Перед
удалением проверил уникальные файлы и перенёс их в песочницу:

- `.../bin/Debug/_legacy_from_diskD/Engine/` — 11 конфигов Самурая и
  «Вечного ФьючЮаня» (оптимизатор, таймфреймы, порты, дефолтные параметры);
- `_legacy_from_diskD/Sets/samurai-def.txt`;
- `_legacy_from_diskD/Data/Set_ВечныйФьючЮань` — 73 МБ, 178 файлов,
  `diff -rq` с оригиналом пустой.

Роботы, исходники и прочий билд 27.10 дублируются в рабочей копии 2.0.2.0.
После удаления MCP продолжает работать из `materials/...` (401 без ключа),
процесс `./OsEngine.exe -data` жив.

## Изменённые файлы

- `docs/how-to.md` — раздел «OsEngine MCP (только исследования)»: единственная
  рабочая копия, команда запуска, проверка handshake, путь к legacy-архиву.
- `PROGRESS.md` — короткая строка в инфраструктуре: 2.0.2.0, 181 инструмент,
  старая копия удалена.
- В старой копии `McpSettings.txt` был возвращён в исходное `False` перед
  удалением (чтобы не оставлять чужих правок).

## Ограничения

- В текущей сессии OpenCode инструменты `osengine_*` не загрузились: remote-MCP
  подключаются при старте сессии. Для работы с ними нужна новая сессия;
  перезапускать `opencode service` на живой сессии не стали.
- `infra/db/memory.db` содержит историческую строку со старым путём — архивная
  запись индекса, не зависимость.

### 14:51 — Конец: восстановление OsEngine MCP и удаление старой копии

**решено.** MCP V2 на `:6500` работает из единственной копии 2.0.2.0 в
`materials/04_Софт_и_инструменты/OsEngine Софт` (181 инструмент, `IsOsData`);
старый `/mnt/DiskD/OsEngine-master` удалён, его уникальные настройки и сет
сохранены в `bin/Debug/_legacy_from_diskD/`. Порядок запуска и проверки —
`docs/how-to.md`, статус — `PROGRESS.md`. OsEngine остаётся research-only
(ADR 18.11), в контур ничего не добавлялось.
