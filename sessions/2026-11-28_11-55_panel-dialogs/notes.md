### 12:10 — Находка в самой headless-проверке
Новая регрессия сначала упала: `document.querySelectorAll(...).click()` не переключает
Radix Tabs (компонент слушает настоящий `mousedown`), поэтому вкладка «Инструменты»
фактически не открывалась. Проверено отдельным puppeteer-скриптом: real `handle.click()`
переводит вкладку в `data-state=active` и показывает фразу «Инструментов в каталоге: …».
Заодно исправлен основной цикл `check-all.mjs`: раньше он тоже щёлкал по вкладкам через
DOM `click()` и собирал в `seen` только подписи самих табов — проверка «содержимого»
вкладок была фикцией. Теперь клики реальные и `seen` содержит текст каждой панели;
`problems=[]`, длины разделов уменьшились (раньше в `seen` попадал только первый таб
с полным списком роботов, теперь — только текущая панель).

### 12:04 — Следующая найденная проблема: прямые ссылки разделов дают 404
При попытке открыть диалог в разделе «Логи» headless получил `{"detail":"Not Found"}`:
сервер отдавал React только для `/`, `/trade`, `/robots`, `/accounts`, `/health`,
`/ui/...`, хотя `App.tsx` при клике по меню пишет `/portfolio`, `/charts`,
`/simulation`, `/history`, `/logs` через `history.pushState`. То есть обновление
страницы в 5 из 7 разделов ломалось (404), а `check-all.mjs` проверял только `/robots`.
Решение (одна завершённая правка):
- `web/app.py`: добавлены маршруты `/portfolio`, `/charts`, `/simulation`,
  `/history`, `/logs` на ту же функцию `react_index()`;
- `tests/test_http_api.py`: тест прямых ссылок расширен до всех семи разделов
  и `/ui/logs`, `/ui/charts`;
- `webui/check-all.mjs`: цикл deep-link по всем разделам с проверкой активной
  кнопки меню; навигация через `domcontentloaded`, чтобы опрос логов не мешал;
- `docs/ONBOARDING.md` и строка `web/app.py` в `docs/MODULES.md` обновлены.
Проверки: `./run.sh test` зелёный, `npm test` 16/16, `npm run build` OK.
