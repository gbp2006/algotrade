# Сессия — источник сигнала живого робота в UI

## 00:16 — причина путаницы

В карточке `prostushka-test-1` видны параметры `ma_window=200`, `entry=13:50`,
но бой берёт сигнал из `p-base` через `source_config`. API уже возвращает
`source_config` (`algo/robot_store.py`, колонка в `instances`), а UI его не
показывал. Решил не переписывать параметры, а явно подписать источник — данные
остаются как есть, у пользователя появляется честный контекст.

## 00:20 — изменения

- `webui/src/lib/types.ts` — поле `source_config` в `Robot`.
- `webui/src/sections/Robots.tsx` — в таблице у живого робота под названием
  «сигнал: p-base»; в мастере при редактировании — предупреждение, что поля
  параметров не управляют сделками, если задан `source_config`; состояние
  сбрасывается при создании/сохранении.
- `tests/test_instances_api.py` — API-тест, что `source_config` доходит до
  `instances_view`, и проверка в тесте исходников UI, что подпись есть.
- `docs/MODULES.md`, `PROGRESS.md` — обновлены.

## 00:22 — проверка и выкладка

`./run.sh test` — 303 теста / 42 файла, 0 падений; `npm test` — 4 зелёных;
`npm run build` — OK (bundle 721 КБ, предупреждение Vite осталось). Коммит
`d255357` запушен; `deploy_wsl.sh --apply` — md5 247 файлов OK, новый ассет
`index-DVxn07Ze.js` выложен и отдаётся панелью (200). На WSL `./run.sh test` —
303 теста, 0 падений; локально `./run.sh check-ui` — 7 разделов, 0 ошибок JS.
`check-ui` на WSL не запускается: там нет `node` — это проверка десктопа.

### 00:24 — Конец: источник сигнала виден в панели

Статус: **решено**. Параметры живого робота больше не выглядят как executable:
в таблице и мастере явно указан `source_config`. Коммит `d255357`, выложено на
WSL, тесты 303/303 и локально, и на WSL. Осталось предупреждение Vite о размере
бандла — на исполнение не влияет.
