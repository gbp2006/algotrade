# Квартальные фьючерсы и перекладка позиций

Проект модуля (23.11.2026). В контур не включён. Вечный `CNYRUBF` перекладки
не требует; правила ниже относятся к Si/RTS/GOLD и другим квартальным контрактам.

## 1. Что есть сейчас

- `algo/instruments.py::contract()` выбирает **ближайший неистёкший** контракт по
  `LASTTRADEDATE` с ISS. Экспирация — третий четверг марта/июня/сентября/декабря.
- `scripts/55_build_continuous_2026.py` строит непрерывные серии по **максимальной
  дневной VOL**, без back-adjustment. То есть бэктест и живой выбор контракта
  выбирают разные ноги в дни, когда ликвидность уже перешла, а дата экспирации
  ещё не наступила.
- `scripts/31_paper_live.py` при смене символа пишет в `paper.csv` одну строку
  «ролл»: закрытие старой ноги по последней цене. Новая позиция открывается
  отдельным решением. Позиции считаются по `config` без привязки к символу.
- Настоящего механизма перекладки (две ноги, контроль исполнения, защита от дня экспирации) в живом контуре нет.

## 2. Принципы

1. **Выбор ноги по ликвидности, а не по дате.** Front-contract = контракт с
   максимальной средней VOL за окно (по умолчанию 5 дней), данные строго до
   дня решения — без look-ahead. Это совпадает с правилом бэктеста.
2. **Не торговать в день экспирации.** Тумблер `trade_on_expiry=false` уже
   запрещает новые позиции в третий четверг; перекладка должна выполняться
   заранее.
3. **Перекладка = две ноги.** Закрыть старую позицию и открыть такую же в новой
   ноге. Обе заявки имеют общий `roll_id` в `client_order_id`; при сбое одной
   ноги контур встаёт на STOP до ручной сверки (нельзя остаться с голой ногой).
4. **Количество 1:1.** Для Si/RTS/GOLD спецификация контракта одинакова между
   кварталами; ratio настраивается, по умолчанию 1.0.
5. **Позиция хранится по (robot, symbol).** В журнале и в брокере перекладка
   меняет символ, не меняя экономическую суть позиции.

## 3. Модуль `algo/rollover.py`

- `front_on(day, contracts, volumes, window=5)` — выбор ноги по VOL за окно до дня;
- `days_to_expiry(day, last_trade_date)` — календарные дни до экспирации;
- `roll_decision(day, held_symbol, contracts, volumes, policy)` — нужно ли
  перекладываться:
  - `policy="volume"` (по умолчанию) — когда front != held;
  - `force_before_expiry=N` — принудительно за N календарных дней до экспирации,
    даже если VOL ещё не перешла;
  - `never` — для вечных контрактов.
- `plan_roll(decision, old_price, new_price, qty, ratio=1.0)` — две ноги с общим
  `roll_id`, ценами и сторонами.

Модуль чистый: не ходит в сеть, не знает про Finam, работает на переданных
данных. Тесты — на синтетических объёмах.

## 4. Интеграция (порядок)

1. Модуль + тесты. **Текущий этап.**
2. Загрузчик VOL из кэша ISS (`cache/iss/*_2026_M5.txt`) и из БД `market.db` —
   единый источник для бэктеста и боя.
3. `34_live_execute.py`: перед расчётом дельты проверить `roll_decision` для
   каждой квартальной позиции; если нужна перекладка — сформировать две ноги
   через `OrderGateway` с общим `roll_id`, не применяя обычный target на этот день.
4. `31_paper_live.py`: заменить «ролл по смене символа» на тот же `roll_decision`,
   чтобы бумага и бой принимали одно и то же решение;существующие id не меняем.
5. Отчёт/панель: показывать перекладки отдельной строкой и в эквити (без искажения
   P&L — закрытие по цене старой ноги фиксирует результат, открытие новой —
   новая сделка).

## 5. Ограничения

- Без back-adjustment исторические серии имеют разрыв цены на стыке контрактов;
  для backtest-сравнений добавить опциональную скорректированную серию (отдельным решением).
- Для 2027 нужно докачать H7/M7/U7/Z7 с ISS — сейчас в кэше только 2026.
- Перекладка в день экспирации запрещена; если VOL не перешла до экспирации,
  срабатывает `force_before_expiry`.
- Торговля квартальными контрактами включается только после отдельного ADR и
  прохождения ворот — сейчас это подготовка.
