# Вороты цикла: тесты → бумага → бой

Живой документ. Статус обновляется по итогам каждой фазы; решения — в `decisions.md`.

| Ворота | Переход | Критерий | Сейчас (23.11.2026) |
|---|---|---|---|
| G1 | тесты → бумага | 30+ зелёных тестов (движок, хранилище, брокер, бумажный контур, сторож); честный backtest (in-sample / OOS / кросс-инструмент / издержки / плато); ADR | ✅ 120 тестов, OOS по трём системам есть |
| G2 | бумага → тень | ≥30 торговых дней; `факт − ожидание = 0` на ≥95% решений; просадка счёта ≤30%; 0 пропущенных таймеров; свежие данные ≤15 мин | ⏳ **3/30** уникальных дат в `results/paper.csv` (19, 20, 23.11); tracking error 0, сторож и дневной отчёт включены |
| G3 | тень → бой | ≥10 дней с реальным Finam API без заявок; сверка денег/позиций с брокером; идемпотентные заявки (`client_order_id`), таймаут/отмена/частичное исполнение; лимиты на заявку/день/номинал; lock от двойного запуска; STOP для реальных ордеров; отдельный `live.csv` | ⏳ **2/10** уникальных дат в `results/live.csv` со статусом `planned` (20, 23.11), всего 10 planned; транспорт к роботу не подключён; режим цены `marketable` и стартовый набор `p-base`/`u-base` на CNY зафиксированы ADR 23.11 |
| G4 | бой → масштаб | ≥1 месяц малого капитала без инцидентов; OOS-метрики не деградировали; каждая нога — новый `config id` + ADR | ❌ не начато; капитал — минимум под 1 контракт CNY (ADR 23.11) |

## Правило счёта дней (единое)

- **G2:** число уникальных значений `date` в `results/paper.csv` (строки с `config`). Календарные дни и выходные не считаются.
- **G3:** число уникальных дат в `ts` строк `results/live.csv` со статусом `planned`.
- Оба значения отдаёт `GET /api/live-state` (`paper_days`) и `GET /api/paper.csv` / `GET /api/live-orders`.
- Перезапуск панели, деплой кода и смена планировщика не сбрасывают счёт: он считается по журналам, а не по счётчику процесса.

## Что сделать до G3 (не включать `FINAM_ALLOW_TRADING=1`)

1. **Исполнение.** ✅ каркас `algo/broker/execution.py` + `place_limit()`,
   схема Finam сверена с документацией: `limit_price`, `client_order_id` ≤20,
   `find_order()` при потере ответа, `cancel_order()`, `order_state()` с долями
   исполнения. Осталось подключить к роботу и провести репетицию.
2. **Сверка.** Ежедневное сравнение позиций и денег счёта `FINAM_ACCOUNT` с
   моделью из `live.csv`; расхождение → проблема в стороже.
3. **Лимиты.** Максимум контрактов и номинал на заявку, дневной лимит убытка,
   потолок экспозиции из `exposure_of(cfg)` (уже есть), запрет торговли в день
   экспирации (в ADR, в код пока не внесён).
4. **Безопасность.** `FINAM_ALLOW_TRADING=0` по умолчанию; реальный STOP помимо
   бумажного; lock-файл на время работы таймера; лог всех HTTP-ответов брокера.
5. **Репетиция.** 10 дней `paper-live` на реальном API с флагом 0: заявки не
   уходят, проверяется весь путь вплоть до отправки заявки.

## Правила во время бумаги

- не менять существующие `config id` — только новые;
- не оптимизировать параметры по двум дням: сначала 30;
- сверять факт с ожиданием каждый день через `./run.sh report` (с 20.11 — в daily-сервисе);
- инцидент/расхождение → запись в `sessions/` и ADR, а не тихая правка кода.
