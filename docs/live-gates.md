# Вороты цикла: тесты → бумага → бой

Живой документ. Статус обновляется по итогам каждой фазы; решения — в `decisions.md`.

| Ворота | Переход | Критерий | Сейчас (20.11.2026) |
|---|---|---|---|
| G1 | тесты → бумага | 30+ зелёных тестов (движок, хранилище, брокер, бумажный контур, сторож); честный backtest (in-sample / OOS / кросс-инструмент / издержки / плато); ADR | ✅ 34 теста, OOS по трём системам есть |
| G2 | бумага → тень | ≥30 торговых дней; `факт − ожидание = 0` на ≥95% решений; просадка счёта ≤30%; 0 пропущенных таймеров; свежие данные ≤15 мин | ⏳ 2 дня, tracking error 0, сторож и дневной отчёт включены |
| G3 | тень → бой | ≥10 дней с реальным Finam API без заявок; сверка денег/позиций с брокером; идемпотентные заявки (`client_order_id`), таймаут/отмена/частичное исполнение; лимиты на заявку/день/номинал; lock от двойного запуска; STOP для реальных ордеров; отдельный `live.csv` | ❌ не начато |
| G4 | бой → масштаб | ≥1 месяц малого капитала без инцидентов; OOS-метрики не деградировали; каждая нога — новый `config id` + ADR | ❌ не начато |

## Что сделать до G3 (не включать `FINAM_ALLOW_TRADING=1`)

1. **Исполнение.** В `algo/broker/finam.py` — лимитная заявка с ценой из спреда,
   `client_order_id`, повтор при 429/401, таймаут, отмена, разбор частичного
   исполнения. Тесты на заглушке — обязательно.
2. **Сверка.** Ежедневное сравнение позиций и денег счёта `FINAM_ACCOUNT` с
   моделью из `live.csv`; расхождение → проблема в стороже.
3. **Лимиты.** Максимум контрактов и номинал на заявку, дневной лимит убытка,
   потолок экспозиции из `exposure_of(cfg)` (уже есть), запрет торговли в день
   экспирации (в ADR, в код пока не внесён).
4. **Безопасность.** `FINAM_ALLOW_TRADING=0` по умолчанию; реальный STOP помимо
   бумажного; lock-файл на время работы таймера; лог всех HTTP-ответов брокера.
5. **Репетиция.** 10 дней `paper-live` на реальном API с флагом 0: заявки не
   уходят, проверяется весь путь вплоть до отправки заявки.

## Правила во время бумаги

- не менять существующие `config id` — только новые;
- не оптимизировать параметры по двум дням: сначала 30;
- сверять факт с ожиданием каждый день через `./run.sh report` (с 20.11 — в daily-сервисе);
- инцидент/расхождение → запись в `sessions/` и ADR, а не тихая правка кода.
