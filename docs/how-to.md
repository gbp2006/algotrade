# Как работать с песочницей

Документ для нового чата/сессии. Прочитать первым, если ты агент.
Держать коротким: 2–3 экрана.

## Точка входа

Рабочая папка: `/mnt/DiskD/opencode-algo`. Данные — симлинк `data/` на
`materials/01_Данные/Исторические данные` (через `data/`) (не открывать файлы данных напрямую!).

Порядок чтения (только это, дальше по необходимости):

1. `PROGRESS.md` — где мы, что проверено, открытые вопросы;
2. `docs/decisions.md` — почему сделано именно так;
3. `docs/strategies/<система>.md` — перед работой над конкретной системой;
4. код — только тот файл, который правится.

## Команды

```bash

./run.sh test       # юнит-тесты движка (~1 с)

```

Полные прогоны — `scripts/NN_*.py`, по порядку номеров.

## OsEngine MCP (только исследования)

MCP V2 живёт внутри терминала OsEngine, отдельного сервиса нет. Если `osengine_*`
не отвечает, проверяют `curl -s -o /dev/null -w '%{http_code}' http://localhost:6500/api/v2/mcp`
(401 без ключа = хост жив, `000` = не поднят). Единственная рабочая копия —
обновлённая 23.11 до 2.0.2.0 внутри `materials/04_Софт_и_инструменты/OsEngine Софт`;
старый `/mnt/DiskD/OsEngine-master` (2.0.1.9) удалён 24.11, его уникальные
настройки Самурая и сет `Set_ВечныйФьючЮань` сохранены в
`.../bin/Debug/_legacy_from_diskD/`. Запуск терминала под Wine с `-data`:

```bash
cd '/mnt/DiskD/opencode-algo/materials/04_Софт_и_инструменты/OsEngine Софт/OsEngine-master/project/OsEngine/bin/Debug'
nohup setsid env WINEPREFIX=/home/zt/.wine WINEDEBUG=-all \
  /opt/wine-stable/bin/wine ./OsEngine.exe -data \
  >/tmp/opencode/osengine-wine.log 2>&1 </dev/null &
```

Если `Engine/McpSettings.txt` в этой копии выключен, 3-я строка (`IsEnabled`)
должна быть `True`. Проверка: `initialize` → `notifications/initialized` →
`tools/list` на `/api/v2/mcp` с заголовком `X-Api-Key: osengine-mcp-default-key`
и `MCP-Protocol-Version: 2024-11-05` (2.0.2.0, 181 инструмент,
`terminal_get_status` → `IsOsData`). Глитчи GUI под Wine не важны — нужен только MCP. Подключать к контуру
запрещено (ADR 18.11); если MCP отвалился после рестарта терминала, инструменты
появятся только в новой сессии OpenCode.

## Цикл работы

```
10_append_iss.py  ->  NN_<задача>.py  ->  results.record()  ->  reports/*.md  ->  PROGRESS.md
```

Правила:

- в консоль — максимум 6 строк на прогон; подробности в `reports/`;
- каждый прогон пишет строку в `results/runs.csv` (`algo.results.record`);
- выводы и статус — в `PROGRESS.md`, решения — в `docs/decisions.md`.

## Новая стратегия: 4 шага

1. `algo/strategies/mybot.py` — одна функция:

   ```python
   def targets(df: pd.DataFrame, **params) -> pd.Series:
       """Целевая позиция в контрактах после закрытия каждого бара."""
   ```

   Никакого исполнения внутри — им занимается `algo/engine.py`.

2. `docs/strategies/mybot.md` — сигнал, вход, выход, фильтры, чего в системе нет.
3. `scripts/NN_mybot.py` — прогон: in-sample, out-of-sample, другой инструмент,
   запись через `results.record`.
4. Строка в `PROGRESS.md`: результат, слабое место, что дальше.

Шаблон: `algo/strategies/_template.py`.

## Протокол проверки (не пропускать)

1. In-sample — CNY 2023–2025.
2. Out-of-sample — 2026 (или любой период, не участвовавший в выборе параметров).
3. Кросс-инструмент — Si 2009–2026.
4. Издержки — при 0/1/3/5 тиках.
5. Плато — сетка параметров; смотреть ширину прибыльной зоны, а не максимум.

Если на шаге 3 результат исчезает — стратегия откладывается, а не дооптимизируется.

## Известные грабли

- **Подгонка**: корреляция PF train↔test у Простушки −0.06 — ранжирование
  параметров не переносится. Оптимизировать бессмысленно, брать середину плато.
- **Выходные**: с 2026 у MOEX есть субботние сессии, они ломают логику «раз в сутки».
  Все прогоны — `skip_weekend=True`.
- **Данные**: апрель 2022 битый (скачок 7.4% за минуту) — тесты начинать с 2023.
- **Издержки**: 5 тиков проскальзывания съедают ~28% прибыли Простушки.
- **Самурай**: не воспроизводится, микроскальперская экономика — см. `PROGRESS.md`.

## MVP: критерии готовности

- считает сигнал по последним данным и знает текущую позицию;
- выдаёт одно действие: купить / продать / держать / закрыть;
- пишет журнал (дата, цена, сигнал, действие);
- громко падает, если данные устарели или подозрительны;
- умеет сверяться с фактом исполнения.

Скрипты: `scripts/20_mvp_signal.py`, `scripts/21_mvp_paper.py`.

## Сервер (боевая площадка)

Песочница развёрнута в WSL Ubuntu на Windows Server 2025 (`192.168.0.230`),
доступ по SSH-ключу:

```bash
ssh wsl-algo                 # порт 2222, ключ ~/.ssh/wsl_algotrading, пользователь zt
cd ~/algotrading
```

Обновить код с локальной машины **только** whitelist-скриптом (секреты,
`data/`, `results/`, `infra/db/` и прочее состояние сервера не трогает):

```bash
./scripts/deploy_wsl.sh              # dry-run: список изменений
./scripts/deploy_wsl.sh --apply      # скопировать и сверить md5
./scripts/deploy_wsl.sh --apply --restart  # ещё и перезапустить панель
```

`--delete` **не применяется**: на WSL живут `.env`, архив, БД и журналы,
которых нет в песочнице. Адрес задаётся `ALGO_WSL`/`ALGO_WSL_DIR`.

Расписание: `algotrading-daily.timer` — будни **13:55 МСК** (`paper-live` +
`update`), `algotrading-morning.timer` — 10:25, `algotrading-friday.timer` —
пт 18:45, `algotrading-update-live.timer` — каждые 10 минут. Логи — в `results/`.
Управлять можно только из root: `wsl -u root` на Windows (или через WinRM).

Проверка после перезагрузки Windows: задача «WSL Algo Boot» поднимает WSL и sshd.

## Бумажный тест конфигураций

Конфигурации — `algo/configs.py`. Добавить новую: создать `Config(...)` с новым id
(старые не менять — иначе рвётся сопоставимость).

Порядок включения реальной торговли — в `docs/live-runbook.md`, маршрутизация
счетов — в `docs/decisions.md` (ADR 27.11). Ворот как процесса нет (ADR 28.11).

```bash
./run.sh paper-live   # записать сигналы (10:25 — выходы, 13:55 — решения)
./run.sh report       # метрики по журналу: дни, сделки, P&L, DD
./run.sh shadow       # репетиция: плановые заявки в shadow.csv, без отправки
```

Сравнивать конфигурации между собой за месяц нельзя — при 6 вариантах лучшая
выходит случайно. Нужен разбор — считайте расхождения локально по журналам.
