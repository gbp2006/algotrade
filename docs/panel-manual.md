# Панель управления — инструкция пользователя

Версия: 26.11.2026. Панель — единственный пульт проекта: бумажные и боевые
роботы, счета, заявки, расписание, STOP и фонд денежного рынка управляются здесь.

## 1. Вход

- Адрес: **http://192.168.0.230:8080/** (все старые пути `/robots`, `/charts` и
  новые `/ui/...` открывают соответствующий раздел напрямую).
- Из песочницы сначала поднять VPN: `nmcli con up "Sysinv SSTP"`, затем браузер.
- Проверка связи: `curl http://192.168.0.230:8080/api/health` → `status: OK`,
  `problems: []`.

Верхняя строка:

| Элемент | Что делает |
|---|---|
| `Все / Тестовые / Боевые` | Фильтр режима роботов и графиков. |
| «Все счета» | Выбор счёта для портфеля и операций. |
| Equity | Сумма equity реальных счетов. |
| «Связь в норме / N предупреждений» | Краткое состояние `/api/health`. |
| Светлая/Тёмная, Компактная/Комфортная | Оформление, сохраняется в браузере. |
| «Торговля: ВКЛ/ВЫКЛ» | Тумблер боевого таймера 14:00 МСК, с подтверждением. |
| «Стоп всех» | Выставляет STOP_REAL: новые входы прекращаются, позиции остаются. |

## 2. Разделы

### 2.1 Портфель и обзор
KPI, кривая капитала в ₽/%, позиции, аллокация, метрики (TWR/MWR/DD/Sharpe/
Sortino/PF/Winrate) и сверка «план/тест vs факт». Источник денег — брокер,
операции обнаруживаются опросом и записываются по id транзакции.

### 2.2 Торговля и графики
- Свечи M1…D; выбор робота/инструмента списком или кликом по карточке справа.
- Слои: «Сделки роботов», «Активные заявки», «Пополнения/снятия» — включают
  маркеры на графике.
- Вкладки: «Свечи и индикаторы», «Сделки роботов», «Заявки брокера»,
  «Пополнения и снятия».
- Если несколько роботов на одном инструменте — предупреждение о корреляции.

### 2.3 Роботы и алгоритмы — рабочий цикл

**Вкладка «Мои роботы»** — таблица всех роботов; живые сверху. У каждого:
статус, счёт, позиция, equity и кнопки:

- **«Старт · торговать»** — одним нажатием переводит робота в `active`, включает
  **его расписание** (твои времена и дни не меняются) и разрешает реальные
  заявки для фонда; для остальных боевых роботов включает таймер 14:00.
- **«Стоп · остановить»** — выключает расписание робота, снимает разрешение на
  реальные заявки и ставит статус `paused` (если живых роботов не осталось —
  выключает и общий таймер).
- **В архив** — убрать робота из активных, не меняя расписание.
- **В бой** — перевод бумажного робота в `live`.
- **Смена счёта** — выпадающий список прямо в ячейке «Счёт», с подтверждением.
- **Закрыть позиции** — для активного боевого робота; реальная отправка только
  при ARM на вкладке «Боевой контур», иначе `dry_run`.
- **Ребаланс фонда / Закрыть фонд** — для `money_market`.
- **Галка «Расписание»** — включает персональное расписание и открывает
  подвкладку «Расписание робота».
- **Настроить** — мастер с текущими параметрами; **Удалить** — только черновик
  или архивный бумажный робот (журнал сделок не трогается).

**Вкладка «Алгоритмы»** — библиотека стратегий с описанием, кнопка «Создать робота».

**Мастер робота** — имя, алгоритм, инструмент (можно взять из вкладки
«Инструменты»), счёт, режим TEST/LIVE, сайзинг, лимиты, SL/TP/трейлинг,
время закрытия и динамические параметры выбранного алгоритма с русскими
подписями. Для боевого робота укажите `source_config` — иначе он не найдёт
решений в `paper.csv` и заявок не будет. «Рассчитать лот» использует реальные
цену и equity из `runtime_state` для существующего робота.

**Параметры «Фонд денежного рынка»** (русские подписи):

| Поле | Смысл |
|---|---|
| Режим работы | Выключен / Дважды в день / Один раз в день / Только закрытие. |
| Тикер фонда | `FMMM@MISX` — БПИФ «Финам — Денежный рынок». |
| Минимальный остаток денег, ₽ | Ниже этой суммы покупки не делаются (5000). |
| Предельный спред, % | Фильтр спреда (0.01%). |
| Время покупки / продажи, МСК | 23:00 / 10:05. |
| Покупать в понедельник…воскресенье | Дни работы робота. |
| Резерв, % / Резерв, ₽ | Неприкасаемый остаток. |
| Минимальная сделка, ₽ | Порог сделки. |
| Максимум паёв в портфеле | `max_units`. |
| **Лимит паёв на заявку, штук** | Свой лимит фонда (по умолчанию 100000). |
| **Лимит номинала, доля капитала** | Свой потолок номинала (по умолчанию 1.0). |

Выделенные лимиты — не лимиты фьючерсного счёта (`max_qty=100`,
`max_exposure=0.5`): паи стоят ~14 ₽, и фьючерсные лимиты блокировали парковку
кэша. Задавай их в карточке робота.

**Вкладка «Боевой контур»**:

1. «Проверить бой (dry-run)» — прогон без отправки, пишет `planned`.
2. «Пустить в бой (arm)» — один реальный прогон, с подтверждением.
3. Таймер постоянной торговли — включить/выключить 14:00 МСК.
4. STOP боя / STOP бумаги и снятие STOP_REAL; видны `FINAM_ALLOW_TRADING`.
5. «Реальная отправка (панель)» — тумблеры **ARM: фонд** и **ARM: закрытие**;
   по умолчанию `dry-run`, включение требует подтверждения.
6. Таблица последних заявок брокера.

**Вкладка «Инструменты»** — поиск по каталогу (~127 тыс. символов), ★ в
избранное, обновление справочника и топ ликвидных MOEX, «Параметры»,
«Создать робота» с выбранным тикером.

**Подвкладка «Расписание робота»** (открывается галкой в таблице) — дни недели,
времена HH:MM, интервал, часовое окно, таймаут, команда. Дефолт берётся из
параметров робота; выключение сохраняет настройки. Именно это расписание
использует кнопка «Старт». Задания роботов исполняются планировщиком; системные
задачи остаются в shadow-режиме и не влияют на торговлю. Для фонда команда
по умолчанию вызывает ребаланс через API панели и сам выбирает режим по времени
слота: вечером (`time_buy`) покупает паи, утром (`time_sell`) продаёт (`OnlyClose`).
Если паёв нет, утренний слот пишет «нечего закрывать» и заявку не отправляет.

**Вкладка «Расписание»** — общие задачи планировщика и журнал запусков.

**Вкладка «Дневник изменений»** — история параметров, счёта и статусов робота.

### 2.4 Тестирование
Список виртуальных роботов и симулятор денежных операций: «лот до → после».

### 2.5 Счета и брокеры
Создание/редактирование/удаление счетов, ключ счёта (секрет — только в
`auth.json`), вкл/выкл, «Опросить счета». Вкладка «Брокеры и коннекторы» —
список адаптеров с кнопкой «Проверить», сервисный ключ, журнал вкл/выкл
торговли. Вкладка «Операции и предпросмотр» — выбор виртуального робота,
пополнение/снятие, применение только к бумаге.

### 2.6 Операции и сделки
Журнал заявок и сделок (`trades.db`) с фильтрами по роботу, счёту и дате,
экспорт CSV. Операции по счетам и история пересчёта лотностей.
`planned` = проверка без отправки.

### 2.7 Логи и диагностика
Единый лог с категориями «Заявки и сделки», «Роботы», «Планировщик»,
«Здоровье и API», поиском, фильтром INFO/WARN/ERROR, JSON-инспектором и CSV.

## 3. Типовые сценарии

1. **Добавить робота по тикеру.** «Роботы» → «Инструменты» → найти тикер →
   «Создать робота» → заполнить мастер → «Создать» → в таблице «Старт».
2. **Проверить бой без риска.** «Боевой контур» → «Проверить бой (dry-run)» →
   «Операции и сделки» → найти `planned` за сегодня.
3. **Запустить реальные торги.** Убедиться в `/api/health: OK`, нет STOP,
   баланс достаточно → тумблер «Торговля: ВКЛ» (таймер 14:00) или «Пустить в
   бой (arm)» для одного прогона.
4. **Парковать свободный кэш в фонд.** «Настроить» у `money-market` → задать
   лимиты и режим → «Старт» → включить «ARM: фонд» → «Ребаланс фонда».
5. **Остановить торговлю.** «Стоп всех» (STOP_REAL) или «Пауза» у робота;
   снятие — «Снять STOP боя» на вкладке «Боевой контур».

## 4. Безопасность

- Реальные заявки идут только по `--arm`, таймеру или тумблеру ARM с подтверждением.
- STOP_REAL блокирует новые входы; открытые позиции остаются у брокера.
- Секреты не показываются в UI и не пишутся в логи — только имена ссылок.
- Бумажный счёт не сравнивается с боевым напрямую: разный капитал и загрузка;
  бумага даёт направление, размер считается от equity боевого счёта.
- При расхождении позиций раннер выставляет STOP_REAL и требует ручной сверки.
