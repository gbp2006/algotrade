# Исполнение заявок: состояние G3

Модуль `algo/broker/execution.py` — **каркас безопасности**, не подключён к
живым роботам. `FINAM_ALLOW_TRADING` на сервере остаётся `0`.

Схема сверена с официальной документацией Finam (getting started, «Безопасно
выставить и отменить заявку», обновлено 28.09.2026):
- лимитная цена передаётся в поле **`limit_price`** (не `price`);
- `client_order_id` — уникальная строка **не длиннее 20 символов** (UUID не
  помещается, шлюз делает sha1 от локального `client_id` и берёт 20 hex-символов);
- отмена — `DELETE /v1/accounts/{account_id}/orders/{order_id}`;
- завершение заявки определяется не одним статусом, а статусом плюс
  `executed_quantity` / `remaining_quantity`;
- если ответ `POST` потерян, **нельзя повторять POST вслепую** — сначала
  сверка активных заявок по `client_order_id`.

## Что уже есть

- `OrderGateway.submit()` перед отправкой проверяет флаг торговли, lock-файл
  `results/live.lock`, повтор `client_id`, лимиты (количество, номинал, дневной
  убыток, список символов), кратность цены шагу `min_step`.
- Журнал `results/live.csv` хранит `client_id`, `client_order_id`, `order_id`,
  статус `blocked / rejected / duplicate / sent / uncertain / error` и причину.
  Lock снимается в `finally`.
- При потере ответа шлюз вызывает `broker.find_order(client_order_id)` и ставит
  `uncertain` вместо повторной отправки — как требует документация.
- `FinamBroker`: `place_limit()`, `order()`, `cancel_order()`, `find_order()`;
  `_call` ретраит 429 и обновляет токен после 401.
- `order_state()` читает статус и доли исполнения; `positions_from_response()` +
  `reconcile()` сверяют позиции модели и брокера. Неизвестный формат — ошибка.
- Тесты: `tests/test_execution.py` (12) + `test_broker.py` (10). Реальный API
  не вызывается.

## Теневой прогон (начался 20.11.2026)

`./run.sh shadow` (`scripts/33_shadow_live.py`) каждый будний день в 13:57 берёт
решения из `paper.csv`, считает дельту позиции, проверяет цену/лимиты через
`OrderGateway(dry_run=True)` и пишет плановые заявки в `results/live.csv`
(статус `planned`). Сводка — `results/shadow.json`, лог — `results/shadow.log`.
Заявки **не отправляются** даже при `FINAM_ALLOW_TRADING=1`. На WSL работает
таймер `algotrading-shadow.timer`. Расхождения позиций с реальным счётом в
бумажном режиме ожидаемы и в дубли не превращаются.

## Что осталось до включения флага

1. **Репетиция 10 дней**: теневой таймер уже считает дни; нужно дождаться
   10 торговых дней без ошибок, затем подключить реальный транспорт.
2. **Подключить к роботу** новым режимом (не меняя `paper-live`): отдельный
   `live.csv`, сверка позиций перед каждым решением, STOP на расхождении.
3. **Лимиты под реальный капитал** — значения по умолчанию (100 контрактов,
   5 млн номинала, 50 тыс. убытка) не являются боевыми.
4. **Цена кратна шагу**: передавайте `Order.min_step` из параметров инструмента;
   без него проверка кратности отключена.

Ворота и критерии — `docs/live-gates.md`.
