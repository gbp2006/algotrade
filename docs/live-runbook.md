# Чек-лист включения реальной торговли (G3 → G4)

> Актуальная модель с 27.11.2026 (ADR в `docs/decisions.md`): отдельного флага
> `FINAM_ALLOW_TRADING`, `--arm` и ARM-тумблеров нет. Заявка уходит только по
> активному роботу на включённом счёте `LIVE` и включённому заданию; управление —
> СТАРТ, СТОП, ЗАКРЫТЬ ВСЁ. STOP_REAL — аварийный тормоз. Ниже — исторический
> чек-лист 23.11, читать с поправкой на эту модель.

Документ описывает порядок действий, а не разрешение торговать. Разрешение — только после
прохождения ворот `docs/live-gates.md` и отдельного решения пользователя.

## 2. Что НЕ делать до прохождения ворот

- Не выставлять `FINAM_ALLOW_TRADING=1` «для проверки» — в `finam.py` прямой
  `place_limit()`/`place_market()`/`cancel_order()` доступен помимо шлюза; пока
  единственная защита — отсутствие вызовов с `dry_run=False`.
- Не менять существующие `config id` и параметры — правило бумажного теста.
- Не оптимизировать параметры по первым 30 дням.
- Не удалять `results/STOP*`, `results/live.csv`, `results/live.lock` без записи в ADR.

## 3. Решения пользователя (23.11.2026)

1. **Цена заявки — решено.** Доступны все три режима, выбор делается на робота
   в `live_settings.json` или в инстансе store: `signal`, `marketable` (по умолчанию),
   `market`. `client_order_id` передаётся во всех режимах. Отклонение от модели
   исполнения ADR 18.11 фиксируется отдельной строкой в ADR, если выбран `market`.
2. **Капитал и лимиты — остаётся открытым.** Пользователь выделит отдельный счёт
   для экспериментов позже. До этого бот не переводится: `battle_limits()` должен
   получить реальный `FINAM_ACCOUNT`, капитал, экспозицию и `max_qty` — не демо-200 тыс.
3. **Набор конфигов на старте — решено.** Роботов в бой пока не переводим: готовим
   переключатель до конца. После ворот — только явно выбранные инстансы через
   `promote` с новым id и ADR; по умолчанию список пуст.
4. **День экспирации — решено.** Реализован тумблер `trade_on_expiry` (по умолчанию
   `false`): в третий четверг квартального месяца новые позиции не открываются,
   закрытие разрешено. Вечный CNYRUBF исключён. Код — `algo/rollover.py`.
5. **Счёт на робота — решено.** Каждый инстанс боя хранит свой `account`, `pricing`,
   `capital`, `exposure`; лимиты и сверка позиций считаются по счёту, а не по роботу.

## 4. Порядок включения (после §2 и §3)

1. Сверить, что 10 дней тени пройдены без инцидентов и пропущенных таймеров;
   ворота G2 упразднены 28.11, сравнение «факт − ожидание» в проект не входит.
2. Сверить деньги и позиции брокера с моделью (`reconcile_guard`), убедиться, что
   `issues` пусто. Любое расхождение → STOP и разбор, не включение.
3. Подключить реальный транспорт **новым режимом**, не меняя `paper-live`: отдельный
  journal `results/live.csv`, `OrderGateway(..., dry_run=False, stop=STOP_REAL,
  limits=battle_limits(...).as_limits())`, `min_step` из `INSTRUMENTS`.
4. Репетиция нового режима с `FINAM_ALLOW_TRADING=0`: все заявки должны писать
  `blocked`, сеть не трогается. Затем 1–2 дня с флагом 0 на том же коде.
5. Включить `FINAM_ALLOW_TRADING=1` на минимальном капитале, малым лотом, вручную
  (не таймером), проверить `live.csv` и выписку брокера. Только после этого — таймер.
6. G4: ≥1 месяц малого капитала без инцидентов; каждая нога — новый `config id` + ADR.

## 5. Экстренная остановка

- `touch results/STOP_REAL` — запрет новых заявок проверяется перед каждой из них.
- `touch results/STOP` — остановка бумажного/теневого контура и таймеров.
- Проверить `results/live.csv`: статусы `uncertain` означают потерю ответа — заявка
  могла уйти; сверяться через `find_order()`, **не повторять POST вслепую**.
- Восстановление — только после записи в `sessions/` и `docs/decisions.md`.

## 6. Настройка через панель (выполняет пользователь)

Порядок на вкладке «Торговля» → `/robots?mode=trade`. Ни один шаг не включает
отправку заявок: нужны ещё отдельный `--arm` и `FINAM_ALLOW_TRADING=1`.

1. **Сервисный ключ.** Поле «Сервисный ключ Finam» — секрет `tapi_sk_…`, кнопка
   «Сохранить сервисный ключ». Он нужен каталогу инструментов, добору данных и
   тени; лежит в `auth.json` под именем `service`, в базу и ответы API не попадает.
2. **Добавить счёт.** ID = `2102993` (числовой из API), номер счёта = `КлФ-2102993`,
   торговый код = `872635RN4O3`, в поле «Секрет Finam для счёта» — его рабочий
   ключ. Размер счёта не задаётся: раннер берёт реальный `equity` у брокера.
   Секрет сохранится в `auth.json`,
   а в карточке счёта останется только имя `acc:2102993`. Ключ робот берёт из
   выбранного счёта — отдельного «ключа робота» нет. Счёт сейчас пуст: без
   пополнения раннер не стартует, нет `equity`.
3. **Добавить робота.** Тип `prostushka`, режим «бой», счёт из п.2, цена `marketable`,
   в поле «Повторяет бумажного конфига» — `p-base` (иначе живой робот не найдёт
   решения в `paper.csv`). Инстанс создаётся черновиком; перевести в `active` вручную.
4. **Проверить**, что `GET /api/accounts` показывает счёт, `GET /api/service-key` —
   что сервисный ключ задан, а `GET /api/keys` — только имена (не значения).
   Запуск таймера и включение флага — отдельные ваши шаги.
5. **Выбрать инструмент.** В форме робота поле «Инструмент» ищет по справочнику:
   по умолчанию — избранное и топ-30 ликвидных с MOEX ISS; переключатель «весь
   каталог» открывает все ~595 тыс. инструментов Финама. Свои инструменты
   добавляются кнопкой «В избранное» и показываются первыми. Обновление топа —
   кнопка «Топ ликвидных с MOEX», полного каталога — «Обновить справочник».
6. **Повторить п.3** для типа `money_market` (`FMMM@MISX`) после того, как отладится
   боевой контур: порядком запуска (пополнение кэша до торгов, парковка после)
   управляет отдельный раннер, который пока не включён. Кнопки «ребаланс» и
   «закрыть фонд» у этого робота работают в режиме `planned`, пока не выставлен
   `ALGO_MM_ARMED=1`.
7. **Кнопка «закрыть позиции»** у живого робота: с подтверждением, пишет закрытие
   в журнал; реальная отправка — только при `ALGO_CLOSE_ARMED=1`. Без этого это
   безопасная репетиция.
8. **Изменение настроек.** Кнопка «изменить» у робота правит счёт, режим цены,
   `source_config` и экспозицию (активный робот уходит на паузу, версия +1).
   Кнопка «изменить счёт» в карточке счёта правит метку, торговый код, экспозицию
   и ключ; новый секрет снова уходит в `auth.json`, а не в БД.
