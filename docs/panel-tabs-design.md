# Панель: вкладки «Тест» и «Торговля»

> Состояние на 27.11.2026: `--arm`, `FINAM_ALLOW_TRADING` и ARM-тумблеры удалены;
> сигнал боя считается по свежим барам (`algo/live_signal`), виртуальный счёт не торгует.
> Актуальная модель — в `docs/decisions.md` (ADR 27.11). Ниже — исторический текст.


Предложение пользователя (23.11.2026): разнести задачи по двум вкладкам, чтобы
бумажная песочница и реальная торговля не смешивались. Проект, выполняется.

## 1. Зачем

Сейчас `/` — это бумажный дашборд, `/robots` — смешанный список инстансов, а
переключатель «Offline / Live» на главной на деле выставляет `results/STOP` для
бумаги. Это опасно: оператор может решить, что включил бой, а он только снял
бумажный стоп. Разделение убирает двусмысленность.

## 2. Разделение задач

| Тест (`/test`, сейчас `/`) | Торговля (`/trade`) |
|---|---|
| бумажные инстансы и их параметры | только инстансы `mode=live` |
| бэктесты, каталог стратегий, OsEngine-идеи | счета, брокеры, сверка позиций |
| данные: ISS/Finam, QA, свежесть | заявки `live.csv`, позиции, P&L счёта |
| `paper.csv`, tracking error, robot_compare | перекладка квартальных контрактов |
| shadow и dry-run репетиции | гейты G2/G3/G4, лимиты, дневной убыток |
| кнопка «Пауза бумаги» (`results/STOP`) | кнопка «Глобальный STOP» (`results/STOP_REAL`) |

Любая заявка в бой по-прежнему требует `FINAM_ALLOW_TRADING=1` **и** `--arm`;
вкладка ничего не включает, она только показывает и останавливает.

## 3. Навигация

В обеих вкладках — верхняя навигация: **Тест** · **Торговля** · **Роботы**.
`/` остаётся совместимым адресом и ведёт в Тест. `/robots` принимает
`?mode=paper|live` и открывает список в нужном контексте.

## 4. Вкладка «Торговля»

Карточки:
1. **Статус**: флаг `FINAM_ALLOW_TRADING`, `STOP_REAL`, ворота G2/G3/G4,
   свежесть данных, последняя проверка брокера.
2. **Счета и брокеры**: список счетов из store, капитал и лимиты, кнопка «проверить».
3. **Боевые роботы**: таблица live-инстансов с id, счётом, режимом цены,
   статусом, позицией; кнопки пауза/стоп.
4. **Заявки**: последние строки `live.csv` (статус, причина, `client_order_id`,
   `order_id`), отдельно подсветка `uncertain`.
5. **Перекладка**: результат последнего `rollover_run.json` и кнопка dry-run.
6. **Управление**: глобальный STOP / снятие STOP только с подтверждением.

Новые API: `GET /api/live-orders`, `GET /api/live-state`,
`POST /api/stop-real`. Существующие `/api/runtime`, `/api/accounts`,
`/api/brokers`, `/api/instances?mode=live` переиспользуются.

## 5. Что НЕ делается

- Не меняется модель исполнения, издержки, конфиги бумажного теста.
- Не снимается `FINAM_ALLOW_TRADING=0` и не запускаются таймеры.
- Не передаются секреты в панель/БД — токены остаются в `.env`.
- Старый `/` не удаляется, чтобы не сломать закладки и скрипты.
