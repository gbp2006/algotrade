# Onboarding — точка входа для ИИ/разработчика

Этот файл читается **первым**. За 5 минут он даёт достаточно контекста, чтобы не
ломать работающий контур. Полный инвентарь частей — `docs/MODULES.md`,
решения — `docs/decisions.md`, текущий статус — `PROGRESS.md`. Пошаговый завод
реальных счетов — `docs/accounts-setup-checklist.md`.

## 1. Что это за проект

Песочница алготрейдинга: исследование стратегий, бэктесты, бумажная торговля,
боевой контур через Финам, web-интерфейс. Всё на одном хосте WSL
`192.168.0.230`, песочница — `/mnt/DiskD/opencode-algo`.

**Это рабочая торговая система, а не только песочница.** Бумажный контур
(17 инстансов) готовит решения, боевой (`prostushka-test-1`, счёт `2102993`)
исполняет их реальными деньгами. **Панель — единственный пульт пользователя**:
все действия доступны из интерфейса, «функция только через curl» не считается
готовой. Проверка перед показом — не только зелёные тесты, но и headless-обход
всех вкладок (`./run.sh check-ui`).

Пользовательская инструкция по панели — `docs/panel-manual.md` (все разделы,
сценарии, безопасность). Полный цикл в панели: «Роботы» → создать робота (мастер) → вкладка
«Инструменты» (найти тикер, ★ в избранное, «Создать робота») → «Мои роботы»
(фильтр `Все/Тестовые/Боевые`, старт/пауза/стоп/архив/«В бой», смена счёта,
закрытие позиций, money-market ребаланс/закрытие) → «Боевой контур» (dry-run
или реальный прогон, STOP, заявки брокера, «Закрыть всё») → «Операции и сделки»
(журнал, CSV). Расписание живёт внутри настроек каждого робота. Кнопка
«Старт · торговать» включает робота вместе с его расписанием и разрешает
реальные заявки; «Стоп · остановить» выключает оба состояния. Расписание
редактируется внутри «Настроить» робота: там же галка включения, дни недели,
времена, интервал, часовое окно и команда (дефолт — из параметров робота).
Планировщик работает в режиме `ALGO_SCHEDULER_MODE=robots`: исполняются
только задания роботов (`inst:*`), системные слоты только логируются как
`SKIP-SYSTEM` — их реально запускают systemd-таймеры. Лимиты фонда задаются его
параметрами «Лимит паёв на заявку» и «Лимит номинала» в карточке робота — это
не лимиты фьючерсного счёта.

**Инварианты (меняются только отдельным ADR):**
- Сигнал по `close` → сделка по `open` следующего бара; `skip_weekend=True`.
- Издержки: 0.01% за сторону + 1 тик; CNY шаг 0.001 × 1000 ₽, Si шаг 1.0 × 1 ₽.
- Счета создаются/правятся/удаляются в разделе «Счета» (`/api/accounts`,
  `/api/keys`); у счёта есть `TEST/LIVE`, `enabled` и `key_ref`. Ключ вводится
  в диалоге «Ключ» и хранится в `auth.json`. Удаление запрещено, если счёт
  привязан к роботу.
- Реальная торговля включается/выключается кнопкой в панели: она разрешает
  задания `inst:*` активных живых роботов, которые исполняет внутренний
  планировщик. Ворота G3/G4 не являются блокировщиком (G2 упразднён 28.11):
  пользователь снял это ограничение.
- Reduce-Only не подключён (ADR 19.11/23.11); дневной лимит убытка и ATR-сайзинг
  удалены полностью (ADR 27.11/28.11). Лот считается только `size_contracts()`.
- Лотность считается **только** через `algo.portfolio.size_contracts()`.
- Секреты — только `auth.json` (600) или `{env:...}`; в API/UI/БД — имена ссылок.

## 2. Стек и адреса

| Слой | Технология | Где |
|---|---|---|
| Движок/расчёты | Python 3.14, pandas/numpy | `algo/` |
| API и раздача UI | FastAPI + uvicorn | `web/` |
| Интерфейс | React 18 + TS strict + Vite + Tailwind/Radix | `webui/`, сборка `webui/dist/` |
| Рабочее хранилище | SQLite (`robots.db`, `trades.db`, `market.db`) | `infra/db/` |
| Целевое хранилище | PostgreSQL 18 + TimescaleDB (опционален) | `infra/db/schema_timescale.sql` |
| Офлайн браузера | IndexedDB через Dexie | `webui/src/lib/offline.ts` |
| Фон | systemd-таймеры и сервисы | `infra/systemd/` |

Доступ к WSL из песочницы — только через VPN `Sysinv SSTP` (NetworkManager,
интерфейс `ppp0`). Если `192.168.0.230` не пингуется, поднять соединение
**самому**, не спрашивая:
```bash
nmcli con up "Sysinv SSTP"   # ppp0, сеть 192.168.100.x
ssh wsl-algo                 # ~/.ssh/config: 192.168.0.230:2222, zt, ~/.ssh/wsl_algotrading
curl http://192.168.0.230/api/health
```
Панель и роботы живут на WSL; на десктопе только код/тесты/проверки. Секреты
VPN и SSH в проект не писать.

Адреса на WSL:
- GUI: `http://192.168.0.230/` (старые пути и прямые ссылки всех семи разделов
  `/portfolio`, `/charts`, `/robots`, `/simulation`, `/accounts`, `/history`,
  `/logs`, а также `/ui/...` отдают тот же React);
- API: `http://192.168.0.230/api/...`;
- локальная dev-копия фронта: `cd webui && npm run dev` → `http://localhost:5180/ui/`,
  `/api` проксируется на `VITE_API_TARGET` (по умолчанию `http://127.0.0.1`, порт 80).

## 3. Команды

```bash
./run.sh test            # все Python-тесты
cd webui && npm test     # Vitest
cd webui && npm run build# сборка в webui/dist
./run.sh check-ui       # headless: 7 разделов, вкладки, правка счёта, deep-link, 0 ошибок JS
./scripts/deploy_wsl.sh --apply --restart                # выкладка на WSL
./run.sh start-project   # НА WSL: PG → миграция → systemd → HTTP-проверка
./run.sh migrate-pg      # однократная миграция SQLite → PG (идемпотентна)
```

Деплой идёт whitelist'ом **без `--delete`**: файлы, убранные из репозитория
или из whitelist, остаются на WSL. Если такой файл — тест, `./run.sh test` на
WSL подхватит устаревший код (например, тест удалённого Jinja-UI). После удаления
файла удаляйте его и на WSL вручную:
`ssh wsl-algo 'rm -f ~/algotrading/tests/<файл>'`.

`scripts/start_project.sh` вызывается при старте/перезапуске WSL: он включает
PostgreSQL, применяет схему и миграцию, чистит `__pycache__` (rsync сохраняет
mtime — иначе сервер поднимает старый байткод) и остатки старого Jinja-UI,
устанавливает юнит `algotrading-web.service` (зависит от PostgreSQL),
перезапускает панель и проверяет HTTP-коды.

## 4. Что где лежит

- `algo/strategies/` — сигналы; ничего не знают про деньги и брокера.
- `algo/portfolio.py` — единственный расчёт лотности; `size_contracts()`.
- `algo/cash_flows.py`, `algo/portfolio_metrics.py` — чистые расчёты потоков
  и метрик (TWR/MWR/DD/Sharpe/Sortino/PF/Winrate/Expectancy).
- `algo/cash_flow_store.py` — новые таблицы в `robots.db`, идемпотентная запись.
- `algo/account_poller.py` — опрос счетов и подтверждение потоков из транзакций
  Финам; `POST /api/cash-flows/sync` и фоновый цикл панели.
- `algo/pg_store.py` — PostgreSQL с DSN только из `auth.json`.
- `web/app.py` — маршруты страниц (React) и часть API; `web/instances_api.py` —
  управление роботами/счетами; `web/cash_flows_api.py` — деньги и портфель.
- `webui/src/sections/` — 7 разделов интерфейса; состояние в Zustand и
  TanStack Query; темы/плотность — `localStorage`.
- `scripts/34_live_execute.py` — боевой контур; перед заявкой свежий equity
  через `account_equity()`; реальная отправка идёт по активному роботу на счёте LIVE и включённому заданию.

## 5. Данные и источники правды

- Деньги: брокер. Пользователь сам пополняет/выводит; проект обнаруживает
  изменения опросом и записывает поток по id транзакции.
- Позиции/заявки: `infra/db/trades.db` (журнал) + ответ брокера.
- Роботы/счета/версии параметров: `infra/db/robots.db`.
- История котировок: `infra/db/market.db`, данные не копируются (`data/` — symlink).
- Снимки equity и потоки: SQLite + PostgreSQL (dual-write); API читает PG,
  если настроен DSN, иначе SQLite.

## 6. Закон цикла: написал → закоммитил → выложил

Любая правка — баг, фича, hotfix или регламент — считается сделанной только
после всех трёх шагов в этом порядке. Исключений нет.

1. **Написать.** Код + тест + строка в `docs/MODULES.md`; `./run.sh test` и
   `cd webui && npm test && npm run build` — зелёные.
2. **Закоммитить и запушить.** Осмысленное сообщение коммита, `git push`.
   Незакоммиченная правка — черновик, а не результат.
3. **Выложить и проверить на сервере.** `./scripts/deploy_wsl.sh --apply
   --restart`, затем `node webui/check-all.mjs http://192.168.0.230/ui/`
   (все 7 разделов, регрессия правки счёта, 0 ошибок JS) и
   `curl http://192.168.0.230/api/health` (`status OK`, `problems=[]`).
   **Не давать ссылку пользователю и не говорить «готово» без этого шага.**

Коммит без выкладки и выкладка без коммита — равно незавершённая работа.

## 7. Что нельзя делать

- Не дублировать формулу лотности в TypeScript — только вызов API.
- Не писать секреты в конфиги, код, логи и чат.
- Не менять модель исполнения и издержки; вкл/выкл торговли — только через
  кнопку в панели (с подтверждением), не прямой правкой `.env`.
- Реальные заявки уходят по активному роботу на счёте LIVE и включённому заданию.
  Фонд и «Закрыть всё» работают без ARM (ADR 27.11); STOP_REAL остаётся
  аварийным тормозом для входов, но не блокирует закрытие позиций.
  «Закрыть всё» всегда привязано к одному счёту — тому, где нажата кнопка.
- Прямые ссылки на разделы (`/robots`, `/charts`, … и `/ui/...`) должны
  открывать соответствующий раздел: URL синхронизирован с состоянием в
  `App.tsx`, не только с localStorage.
- Не удалять старые API-ответы: добавлять поля, не ломая контракт.
- Не запускать панели/сервисы на десктопе — только код/тесты. Любая правка
  (баг, фича, hotfix) обязательно коммитится, пушится и выкладывается на WSL;
  «написал и забыл выложить» — незавершённая работа.
