# AGENTS.md — песочница алготрейдинга

Правила для агентов. Цель: рабочая система, которой управляют из панели;
минимум токенов, максимум повторяемости.

## Цель и режимы работы

- Проект — полноценная торговая система с двумя равноправными контурами:
  **бумажный** (проверка гипотез, обучение) и **боевой** (реальные деньги через
  Финам). Боевой — конечная цель, бумага готовит решения.
- **Панель (`http://192.168.0.230:8080/ui/`) — единственный пульт пользователя.**
  Любое действие, нужное для работы — добавить робота, добавить/выбрать тикер,
  просмотреть заявки и сделки, запустить и остановить торги любым роботом,
  закрыть позиции, ребаланс/закрытие фонда, ключи, счета, расписание, STOP —
  должно иметь кнопку или форму в интерфейсе. **API без кнопки в UI —
  незавершённая фича и не принимается как сделанное.**
- Новый или изменённый endpoint обязан получить кнопку/форму в `webui/src` в
  той же правке; нельзя оставлять «функцию только через curl».
- Боевые проверки — сначала только чтение (журнал, `/api/health`, позиции и
  заявки брокера, STOP/локи, `runtime_state`). Отправлять заявки, менять STOP и
  настройки — только по явному решению пользователя.
- Реальная отправка — только по явному разрешению (`--arm`, тумблер в панели,
  `ALGO_*_ARMED` с подтверждением); по умолчанию `dry-run`/`planned`.
- Бумажный и боевой счета не сравнивать напрямую: разный капитал и загрузка.
  Бумага даёт направление (`signal`), размер считается от `equity` счёта.

## Что читать в первую очередь

1. `PROGRESS.md` — состояние проекта, цифры, открытые вопросы (~3 КБ).
2. `docs/decisions.md` — только последние 30 решений; старые ADR — архивы
   `docs/decisions-archive-2026-11-24.md` и `docs/decisions-archive-2026-11-26.md`
   (искать grep/memory, не читать целиком).
3. `docs/ARCHITECTURE.md` — состав и статус систем; `docs/strategies/*.md` —
   канонические описания; `docs/live-runbook.md` — порядок боевого прогона.
4. Код — только тот файл, который правишь.

**Никогда** не читать файлы из `data/` (гигабайты) и не выводить в чат длинные таблицы.
Скрипты обязаны печатать не больше 6 строк сводки; подробности — в `reports/`.

## Бюджет контекста

- Большие `docs/`, `reports/`, `sessions/*/notes.md` не грузить целиком:
  `./infra/db/memory.py brief|lookup|search|outline` (или `grep`), затем точечный
  `read` нужного диапазона. История не теряется — она в архивах и индексе.
- Одна сессия — одна тема; новую тему начинать новой сессией, законченную
  закрывать записью «Конец:» (skill `session-workflow`). Сессии в сотни реплик
  раздувают повторное чтение контекста и ухудшают ответы.
- После крупного исследования или правки обновить `PROGRESS.md` **короткой**
  строкой + ссылкой на отчёт, а не переносить детали в точку входа.
- Автоматика: `opencode.jsonc` компактирует при ~65% окна и режет длинные выходы
  инструментов; каждые 4 часа automation зовёт `python3 scripts/94_context_cleanup.py`
  — принудительный `/compact` крупным активным сессиям + уход за файлами.
  Урезку `PROGRESS.md`/`decisions.md` скрипт только предлагает, не делает.

## Сессии и память

- Запуск: алиас `algo` — изолированный профиль OpenCode (свои конфиг, БД
  сессий и фоновый сервис).
- Папка сессии: `sessions/YYYY-MM-DD_HH-MM_slug/notes.md`; подробности —
  skill `session-workflow`.
- `INDEX.md` — производный от `sessions/`; статусы тянет
  `./infra/db/memory.py index-sync` из записей «Конец:».
- История: `./infra/db/memory.py brief|lookup|search|outline` или MCP `memory`.
- В индекс входят `sessions/`, `PROGRESS.md`, `docs/`, `reports/`; данные,
  материалы, кэш и код — нет.

## Обязательные правила

- Новый прогон → строка в `results/runs.csv` через `algo.results.record()`.
- Вывод в консоль: `name, сделок, net, PF, DD` — одна строка на вариант.
- Большие выгрузки — в `reports/`, а в чат только путь.
- Данные не копировать: `data/` — симлинк, чтение через `algo.data.load_txt`.
- Тяжёлые данные кэшировать: `algo.data.load_cached()` (pickle в `.cache/`).
- Меняешь модель исполнения или издержек — сначала обнови `docs/decisions.md`.

## Модель исполнения (не менять молча)

- сигнал по `close` бара → сделка по `open` следующего бара;
- комиссия 0.01% за сторону, проскальзывание 1 тик;
- CNY: шаг 0.001, множитель 1000 ₽; Si: шаг 1.0, множитель 1 ₽;
- решения по субботам/воскресеньям отключаются (`skip_weekend=True`).

## Две среды: десктоп-песочница и тестовый сервер (WSL)

- **Песочница — этот ПК** (`zt-desktop`, проект в `/mnt/DiskD/opencode-algo`,
  OpenCode-профиль `algo`): единственное место, где работает агент — проверка
  гипотез, код, выкачивание данных, юнит-тесты, бэктесты, локальная панель
  (`./run.sh dash`), ручные прогоны, правки движка/стратегий.
- **WSL** (`zt@SERVER`, SSH `wsl-algo` → `192.168.0.230`, проект в `/home/zt/algotrading`)
  — **тестовый сервер, где работают торговые роботы**, а не песочница: там
  живёт веб-панель (`algotrading-web.service`, :8080), сервисы таймеров
  (`algotrading-daily/morning/friday`) и бумажный контур по живым котировкам
  (`paper-live`). OpenCode и агентских сессий там нет.
- **На этом ПК (десктопе) никаких панелей и сервисов роботов не запускать** —
  только код, тесты, бэктесты, выкачивание данных, локальная проверка.
- Песочница (`algo`) есть **только на ПК и не дублируется** на WSL: правки в
  код/скрипты/исправления сначала **коммитятся в git-репозиторий** на ПК
  (локально + `git push` на https://github.com/gbp2006/algotrade), и только
  после этого копируются на WSL (минимальный набор файлов + скрипт исправления)
  при необходимости, затем перезапускается сервис на WSL через sudo.
- Если правка относится к торговым роботам (панель, таймеры, watchdog, конфиги
  сервисов) — она пишется и проверяется на WSL, а не на десктопе.


## MCP-профили (24.11)

Рабочий конфиг `opencode.jsonc` генерируется из `infra/config/opencode.base.jsonc`
и фрагмента `infra/config/mcp/<профиль>.json` скриптом `scripts/96_mcp_profile.py`:

- `work` — только `memory` (по умолчанию, минимальная стоимость реплики);
- `research` — `memory`, `websearch-local`, `exa`, `osengine`;
- `broker` — `memory`, `finam-mcp`.

Смена профиля подхватывается только новой сессией после перезапуска сервиса
OpenCode. Старый конфиг сохраняется в `infra/config/opencode.prev.jsonc`.

## Разделение песочниц (24.11)

- `algo` (`/mnt/DiskD/opencode-algo`, профиль `opencode-algo`) — только торговля,
  роботы, алгоритмы. Индекс `infra/db/memory.db` и история `sessions/` — только algo.

  их суть уже в `sessions/*/notes.md`, дублирующий FTS-индекс не строим.
